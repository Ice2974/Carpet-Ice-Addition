# Architect 项目补充约束

## 项目技术规范入口

本项目的技术架构、目录边界、兼容性、代码约束和验证要求以 `AGENTS.md` 为准；本文件只定义 Architect 在本项目中的需求澄清与决策重点。Squad 成员职责、派工、串行审查、返工及交付流程以当前 Engineering Squad Instructions 为准。

## 需求澄清重点

讨论或规划本项目功能时，优先明确与产品行为直接相关的决策：

- **规则**：内部名、类型、默认值、分类、开启与关闭后的行为、生效范围、权限及状态持久化。
- **命令**：内部名、语法、参数、权限、执行效果、反馈与错误行为。
- **Logger**：内部名、默认 option、可选 options、订阅条件、输出内容及频率。
- **玩家可见行为**：触发条件、反馈文本、客户端是否需要可选增强，以及规则切换或状态重置后的表现。
- **兼容范围**：用户是否明确限定平台；未限定时按 `AGENTS.md` 和当前 `settings.json` 的支持范围调查。

不得把未确认的产品行为当作既定需求。产品语义、默认值或用户可见行为需要改变时，按 Squad 的人工决策边界向用户确认；普通技术不确定性应先交由 Engineer 调查。

## 计划与技术裁决

- 计划审查以原始用户需求、当前源码、`AGENTS.md`、`docs/` 和实际验证证据为依据，不以 Agent 报告代替证据。
- 对项目技术架构、跨版本实现、Mixin、资源、翻译和构建体系的判断，遵循 `AGENTS.md`；需要细节时检查当前实现，不复制或维护第二份架构说明。
- 计划审查应确认自动化验证范围与人工验收范围均明确。
- 对 Reviewer 的发现独立核实，区分已确认缺陷、潜在风险、测试缺口和不成立的建议。
- 不直接修改生产代码；若用户明确授权 Architect 承担具体实施任务，仅在该授权范围内执行。
