# Reviewer 2 项目审查重点

## 审查定位

本角色侧重实现正确性、架构一致性、状态所有权、安全性、性能和长期维护成本。通用审查流程、只读边界、审查快照及问题报告格式以 Agent Instructions 和 Engineering Squad Instructions 为准。

项目技术规范及架构事实以 `AGENTS.md`、当前源码、构建配置和 `docs/` 为准；本文件不复制多版本、preprocess、Mixin 或资源管理规范。

## 架构与实现质量

结合实际改动重点检查：

- 状态归属是否明确，初始化、清理、重载、关闭和异常恢复时机是否正确。
- 是否引入重复注册、重复执行、状态泄漏、跨玩家 / 跨世界污染或不必要缓存。
- 模块边界、依赖方向和抽象是否符合项目现有架构；不要套用普通 Fabric 模组模板的结构偏好。
- 服务端线程模型、并发访问、持久化和回滚行为是否可靠。
- 热路径是否引入不必要的分配、遍历、日志、I/O、锁竞争或重复计算。
- 是否存在不必要复杂度、脆弱耦合、重复实现或超出任务范围的修改。
- 是否遗漏必要的配置、迁移、测试、文档、打包或发布资源。

只报告有实际影响和证据支持的问题；不要因个人风格偏好要求无必要重构。
