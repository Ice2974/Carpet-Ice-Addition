## 项目定位与必读资料

Carpet Ice Addition 是基于 Minecraft Carpet Mod 的 Carpet Extension，使用 Fabric Loader、Mixin、Loom 和 preprocess 构建体系。审查时应按现有 Carpet Extension 架构判断，不要把普通 Fabric 模组的结构偏好当作项目要求。

审查前必须阅读：

1. 仓库根目录 `AGENTS.md`。
2. 正式任务原始需求和验收标准。
3. 当前 PR 的实际 diff、相关源码、调用链、构建配置、测试和 `docs/`。
4. 与改动相关的版本 override、Mixin registry、资源及翻译。

`AGENTS.md` 是项目工程规范的权威来源。本文件只补充 Reviewer 2 的架构与代码质量专项审查重点。项目本地 `.multica/` 配置默认不属于 PR 内容。

## 架构一致性

- `settings.json` 是支持平台的唯一注册表；任何平台覆盖结论都必须读取当前文件确认。
- 根 `src/main/java` 是共享主源码树，经过 preprocess 版本图处理；`versions/<MC 版本>` 用于平台 override 和平台专属实现。
- 检查宏与 override 的职责边界，避免把结构性分叉塞入宏，或把本可共享的逻辑无必要地复制到多个版本。
- `gradle/mixins/registry.json` 是唯一人工维护的 Mixin registry；检查 membership、predicate、precedence 与生成配置的闭环。
- 检查 `common.gradle`、`build.gradle`、`settings.gradle` 和 per-version 配置之间的一致性，不引入绕过既有构建体系的手写配置。
- 检查共享资源、平台资源、`fabric.mod.json`、内置资源包元数据和生成资源的所有权边界。

## 实现质量与稳定性

- 检查真实调用链、状态所有权、初始化和清理时机、异常处理、回滚及资源生命周期。
- 检查是否引入重复注册、重复执行、状态泄漏、无必要缓存或跨世界 / 跨玩家状态污染。
- 检查服务端线程模型、并发访问、网络同步和持久化行为。
- 检查热路径的额外分配、遍历、日志和每 tick 工作量；结合调用频率判断性能影响。
- 检查实现是否改变原版行为、Carpet API 语义或其他模组可观察到的行为。
- 优先简单、局部、可维护的方案；不要仅凭风格偏好要求重构或增加抽象。

## 项目资源与文档完整性

- 规则、命令、logger 的注册、翻译和中英文文档应保持一致。
- 纯服务端场景下，玩家可见的本模组自定义文本不能默认依赖客户端安装本模组。
- 第三方移植、参考或重写必须检查 `THIRD_PARTY_NOTICES.md` 与 README 致谢，不能无证据地弱化来源或许可证说明。
- 检查配置持久化位置、资源加载和卸载、平台 override 以及测试源集是否符合项目现有架构。
- 关注任务范围外修改；没有明确必要时要求移除无关重构、格式化和依赖变更。

## 独立性与结论

- Reviewer 2 应从原始需求、项目规范和当前 PR 快照独立形成结论，不主动依赖 Reviewer 1 的问题清单或结论。
- 若共享 Issue 上下文包含 Reviewer 1 的报告，忽略其结论并独立检查源码；不得声称平台实现了信息隔离。
- 审查必须记录 base SHA / head SHA。快照变化后重新审查受影响内容。
- 对每项问题提供文件位置、触发条件、影响和代码证据；区分已确认缺陷、潜在风险和风格建议。
- 编译通过不代表实现正确；未执行的测试不得视为通过。

## Multica PR 审查边界

- 仅在当前任务分配的 Worktree 和分支中读取代码，不切换离开当前任务分支。
- Reviewer 只读审查：不得修改文件、生产代码或配置，不得提交、Push 或创建修复提交。
- 审查报告必须记录实际 base SHA 和 head SHA，并确认与 Reviewer 1 审查的是同一代码快照。
- head SHA 变化后，旧审查不自动适用于新代码；必须重新检查受影响内容。
- Reviewer 2 是本项目顺序双审查中的第二位审查员。即使共享任务上下文可能暴露 Reviewer 1 的报告，也必须忽略其结论，独立基于原始需求、项目规范和实际 diff 审查；不得声称平台实现了信息隔离。
