## 项目定位与必读资料

Carpet Ice Addition 是基于 Minecraft Carpet Mod 的 Carpet Extension，使用 Fabric Loader、Mixin、Loom 和 preprocess 构建体系。

审查前必须阅读：

1. 仓库根目录 `AGENTS.md`。
2. 正式任务原始需求和验收标准。
3. 当前 PR 的实际 diff、相关源码、调用链、构建配置、测试和 `docs/`。
4. 与改动相关的版本 override、Mixin registry 和资源。

`AGENTS.md` 是项目工程规范的权威来源。本文件只补充 Reviewer 1 的项目专项审查重点。项目本地 `.multica/` 配置默认不属于 PR 内容。

## 第一优先级：纯服务端与客户端兼容

- 未安装 Carpet Ice Addition 的原版客户端必须能够正常加入服务器。
- 不得接受新增强制客户端安装、登录握手、客户端专属协议或必需客户端资源的实现。
- 若改动包含可选客户端增强，检查其是否真正可选，以及无 Mod 客户端是否仍能正常连接和使用基本功能。
- 检查服务端向玩家发送的自定义文本是否依赖客户端加载本模组语言文件。

## 功能行为与游戏机制

结合改动涉及的机制检查：

- 正常路径、异常路径、边界条件和状态切换。
- 服务器启动 / 关闭、玩家登录 / 退出、世界加载 / 卸载及资源重载等生命周期。
- 多玩家、多世界、多维度、重启和重复触发。
- 红石时序、生电机器、刷怪效率、区块加载、实体 AI 和服务器 tick 性能。
- 规则关闭 / 开启、配置变化和故障恢复是否保留预期状态。
- 与 Carpet API、Minecraft 原版和其他模组的行为兼容。

不要仅因实现“看起来更快”就认定优化有效；需要结合实际调用频率、调用链和可验证的性能依据判断。

## 多版本与 Mixin 兼容

- 以当前 `settings.json` 为准核对所有受影响平台，不使用历史版本数量或记忆中的版本列表。
- 检查 preprocess 宏是否只承担适合的小差异，结构性差异是否由平台 override 表达。
- 检查 Mixin 目标、方法签名、注入点、注入顺序及 registry 的 membership / predicate / precedence。
- 检查生成的 Mixin 配置是否覆盖正确平台，以及其他模组可能存在的注入冲突。
- 对 API / Mixin 差异提供源码或映射依据；无法确认时标记为待确认，不作确定性判断。

## 测试与交付审查

- 检查测试是否覆盖正向、反向、边界、生命周期、规则切换、重启和多维度等相关场景。
- 区分代码级自动化验证、自动运行时验证和人工游戏内验收。
- 对红石 / 生电机器、刷怪塔、多玩家和客户端行为等难以自动化的内容，提出可执行的人工验收步骤。
- 检查规则、命令、logger 对应的中英文文档、翻译、资源和第三方来源声明是否遗漏。
- 不把未执行的游戏内测试、服务端启动测试或客户端兼容测试标记为通过。

审查结论必须建立在实际 PR 快照和证据上；报告 base SHA / head SHA、问题触发条件、影响范围和严重程度。
