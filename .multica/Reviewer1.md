# Reviewer 1 项目审查重点

## 审查定位

本角色侧重功能行为、真实执行路径、边界条件、运行时表现、兼容性和测试覆盖。通用审查流程、只读边界、审查快照及问题报告格式以 Agent Instructions 和 Engineering Squad Instructions 为准。

项目技术规范及具体实现约束以 `AGENTS.md`、当前源码和 `docs/` 为准；本文件只定义本角色在本项目中的审查侧重点。

## 游戏行为与回归风险

结合实际改动检查：

- 正常路径、异常路径、边界条件，以及规则或配置切换前后的行为。
- 服务端启动 / 关闭、玩家登录 / 退出、世界加载 / 卸载、资源重载等相关生命周期。
- 多玩家、多世界、多维度、重启、重复触发及状态清理。
- 红石时序、生电机器、刷怪行为、区块加载、实体 AI 和服务器 tick 热路径。
- 与 Carpet API、Minecraft 原版及其他模组交互时的可观察行为变化。

不要仅凭实现意图判断功能正确；应沿实际调用链确认触发条件、状态变化和结果。

## 多版本行为验证

- 以当前 `settings.json` 和实际源码为准判断受影响平台，不使用记忆中的版本清单。
- 重点识别同一功能在不同平台上的行为差异，以及 preprocess / override 对执行路径的影响。
- 涉及 Mixin 时，结合实际目标方法、调用点和生成配置判断注入是否生效；具体 registry 和构建约束遵循 `AGENTS.md`。
- 测试缺口应指出对应功能范围和风险。
